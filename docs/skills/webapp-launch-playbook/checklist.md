# 上线前检查清单

> 打勾全部通过再上线。带 ⚠️ 的是本项目实际漏掉或踩过的项。

## 一、功能与数据

- [ ] 核心链路端到端跑通（输入 → 处理 → 输出）
- [ ] 空数据、异常数据、超大输入都有合理表现
- [ ] 每位用户的写操作都有唯一约束兜底
- [ ] ⚠️ 数据质量抽查过（不只看"处理了多少条"，要看字段完整率）
- [ ] ⚠️ 迁移后对账完成：条数、金额、分布差异都有解释
- [ ] 重复提交是幂等的（同样的数据传两次结果一致）
- [ ] 删除/覆盖操作有二次确认或备份

## 二、安全

- [ ] ⚠️ `.env` / 数据库文件 / 私钥不在 git 里（`git log -p | grep -i secret` 无命中）
- [ ] 密码是哈希存储，不是明文
- [ ] 数据库端口公网不可达（只有本机能连）
- [ ] 外部 API 有鉴权（Token / API Key），不是裸奔
- [ ] 安全组只放行必要端口（22 + 业务端口）
- [ ] 服务器 root 密码/密钥不由多人共享
- [ ] 用户输入进 SQL 用的是参数化查询，不是字符串拼接
- [ ] 文件上传有类型和大小限制

## 三、部署

- [ ] ⚠️ 应用监听 `0.0.0.0` 而不是 `127.0.0.1`
- [ ] ⚠️ 用 systemd/容器托管，不是 nohup
- [ ] ⚠️ `systemctl enable` 已设置（重启服务器能自动起）
- [ ] 服务崩溃能自动重启（`Restart=always`）
- [ ] 依赖全部钉了版本
- [ ] ⚠️ 2G 内存机器没装 PyTorch 这类巨型依赖
- [ ] 已加 swap（内存 ≤ 2G 的机器）
- [ ] 时区设置为 `Asia/Shanghai`
- [ ] 换一台干净机器能在 30 分钟内重建（有文档或脚本）

## 四、可观测性

- [ ] ⚠️ 有健康检查（Web 端点 + 进程 + 数据库）
- [ ] ⚠️ 有告警通道（IM/邮件），且**实测过能收到**
- [ ] 告警有去抖（连续 N 次失败才发）
- [ ] 告警有收敛（持续故障不刷屏）
- [ ] 日志能定位问题（至少包含时间、模块、错误原因）
- [ ] 有一键状态查看脚本（`status.sh`）
- [ ] 知道去哪看日志（`journalctl -u xxx -f`）

## 五、文档

- [ ] README 有：项目简介、架构图、功能列表、启动方式
- [ ] 部署文档能照着从零重建
- [ ] `server/` 或部署脚本在仓库里
- [ ] ⚠️ 有「已知限制」章节（诚实记录，别隐藏）
- [ ] 环境变量有 `.env.example` 模板（不含真实值）
- [ ] 运维命令清单（重启、看日志、查状态）

## 六、成本

- [ ] ⚠️ 知道哪些费用是"免费额度"、哪些"按量计费"
- [ ] 账户有余额（或设置了余额告警）
- [ ] 带宽计费方式已确认（按流量 vs 固定带宽）
- [ ] 没有买错产品（云数据库 ≠ 云服务器）

## 七、收尾

- [ ] ⚠️ 临时开的服务/端口已关闭（`systemctl disable --now`）
- [ ] 测试数据已清理或明确标注
- [ ] 代码已推送远程（不是只在本地/U 盘）
- [ ] 关键分支清楚：哪个是线上版本
- [ ] 备份策略明确（数据库至少每天一份）
